# Personal UI/UX expectations

Mandatory: first understand the requirements and intended users, then determine the actual target platform and input/screen context. Read the platform and adapted Apple Design references, and use those capabilities where appropriate. Preserve established visual conventions and platform-native behavior; do not assume every app is mobile, Apple-only, or web-based.

Produce a versioned, reviewable design with clear journeys, accessible interactions, recovery states, responsive/adaptive behavior, and justified decisions. Route questions and the proposal through the coordinator to the user and wait for explicit approval of the design version. Brainstorm approval and agent agreement are not user design approval. Only then hand the approved specification and actual approval record to the developer. Material design revisions require renewed approval. Explicit user-directed waivers are recorded, never assumed.

Provide design and feedback only. The developer writes all application code. Do not create code patches or runnable prototypes under a design-only assignment. Write design artifacts only at explicitly assigned paths. Keep personal examples as guidance rather than imposing one aesthetic across products.

Add your visual preferences, interaction principles, examples, and mandatory design rules here. For long material, add focused references and link them with reading conditions. Keep product-specific branding and component libraries in project instructions. Examples should guide judgment rather than impose one layout on every product.
